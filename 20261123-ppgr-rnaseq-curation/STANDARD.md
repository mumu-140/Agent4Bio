## 0. 口径（用户定）

- **只要是 bulk RNA-seq 就都要**：不限来源。INSDC（ENA/NCBI/DDBJ）、NGDC GSA、文献数据全收。
- **单细胞 RNA-seq 不要**（用户 2026-11-23 定）：library_selection 含 "single cell"、或
  study/sample 元数据明确单细胞（10x / Chromium / Drop-seq / Smart-seq / CEL-seq 等）的 run
  一律剔除，EVIDENCE.md 记剔除数。计数阶段的 experiment 数是未剔单细胞的上界。
- 仍排除：非 RNA-Seq 策略（WGS、miRNA-Seq、ncRNA-Seq、Amplicon 等）、非目标物种的 run。
- **补充行策略过滤**：任何补充来源并入前必须按 library_strategy 过滤——只收 RNA-Seq 与链特异性 RNA-Seq；DNA 类策略（全基因组重测序、亚硫酸氢盐测序、ATAC、Hi-C 等）与小 RNA 测序一律不进 JSON。策略字段缺失时按 study 题名/实验描述人工定性，定性不了的不进。审计结果（各策略行数）记 EVIDENCE.md。

## 1. 契约（Genome-web contracts.md R02 / R03）

- **R02 守恒**：ENA in-scope run 集 == NCBI in-scope run 集；表头驱动解析。
- **R03 元数据 schema**：唯一 ID 优先（study_accession、experiment_accession、run_accession），
  其后事实列 project_name、species_label、genus_species、variety、tissue、treatment、genotype、
  growth_time、default_used、evidence、confidence、curator；原始 ENA 值不改写；
  缺失 = 空串（NULL），绝不写 0；默认值只允许 genotype=WT / tissue=whole_plant /
  treatment=control，且必须在 default_used 留痕。

## 2. 输出 schema（expression-metadata.json）

```json
{"schema_version": 1,
 "source_sha256": "<基线源 TSV 的 sha256>",
 "source_label": "<Species> RNA-seq 策展元数据 / YYYY-MM-DD 导出",
 "rows": [{"study_accession": "", "experiment_accession": "", "run_accession": "",
           "sample_accession": "", "tissue": "", "treatment": "", "genotype": "",
           "growth_time": "", "default_used": "", "confidence": "", "assay": "unreviewed"}]}
```

每行恰好 11 键；`assay` 全为 `"unreviewed"`；`confidence` ∈ {`H`, `M`, `""`}。

## 3. 批量方法（试点实测结论）

1. **先解析接受名，再查数**：每物种先做 NCBI taxonomy + POWO/FoC 接受名核对，异名表写进
   EVIDENCE.md。禁止按俗名直取第一个 taxid（见 PITFALLS #1）。
2. **以 NCBI 为主**：NCBI SRA esearch 计数 + runinfo 展开到 run（Count 计 experiment 不计 run）。
   ENA 按 BioProject 补拉。每个物种做 NCBI−ENA diff，差异逐条定性。
3. **ENA tax_eq 不可单独作准**：会漏 tax_id 为空的 DDBJ 提交、属级登记、近期未镜像提交。
4. **SAMD 样本属性走 ENA sample API，SAMN 走 NCBI efetch**。SAMD 号走 NCBI efetch 会返回
   毫不相干的人类 GTEx 记录。
5. **ENA 列顺序与请求不一致**，解析必须表头驱动。
6. **属级登记**（taxid 为属级）：只有经 BioProject 题名/论文双重核实为本种的才计入，
   并在 EVIDENCE.md 写明。
7. **GSA 枚举走浏览器，不走 curl**：GSA 浏览/搜索页有 JS cookie 校验（SecurityCheck），
   沙箱与 fwq 的 curl 均被拦、只返回校验页；真实浏览器可正常通过。批量时每物种的 CRA→CRR
   枚举用浏览器任务做；实在取不到 CRR 的，先记 CRA 级并标注“CRR 未枚举”，不阻塞主流程、不编 CRR 号。
8. **单细胞剔除**：ENA `library_selection` 含 "single cell" 即剔；无该字段时看 study 题名/
   sample 属性（10x、Chromium、Drop-seq、Smart-seq、CEL-seq 字样即剔）。剔除数记 EVIDENCE.md。
9. **补充行策略过滤**：见 §0。补充路径并入前逐行核策略，策略缺失人工定性；审计表留档。
10. **DDBJ 样本走 DDBJ Search 条目页**：`https://ddbj.nig.ac.jp/search/entry/biosample/<accession>/`（条目页含完整属性，可下载 JSON）。getentry 按猜测的数据库名拼 URL 返回的只是检索页，不可作凭。ENA 仍查不到的 DDBJ-only 近期提交，先走 DDBJ Search 核对，不直接判“无数据”。
11. **每物种必留样本属性缓存**：每物种把读过的样本属性（sample_accession、tissue、treatment、genotype/cultivar、标题/描述原文）存一份机器可读文件 `work/agent-x/<slug>/sample_attrs.tsv`（与 JSON 同级，不进 tmp/、不进 output/），复核不重新联网。没有缓存的物种视为未完成审核。
12. **默认矛盾内置扫描**：策展完成、交付之前，对全部带默认值的行做一次关键词扫描（treatment/tissue 词表由各物种样本原文归纳），凡样本原文与默认值矛盾的逐 study 裁定；扫描规则、裁定记录进 EVIDENCE.md。事后补裁定不是流程。
13. **H 口径**：H 仅当 tissue、treatment、genotype 三字段在 JSON 里均为实证值（即 default_used 为空且 genotype 非空）；任一字段仍是默认值即至多 M。不得以“品种有记录但 genotype 栏未改”给 H。
14. **分类提取（总则）**：处理、基因型、组织、生长时间四字段不得从单一栏位直取，也不得把整段原文照搬进字段。证据分四层，按优先级取用——L1 样本结构化属性（处理、基因型、分离株、品种、发育阶段、年龄、组织、描述原文）与样本库别名/描述；L2 样本标题与实验标题（去掉平台前缀）；L3 研究标题（只提供词汇与上下文，绝不把研究级的值赋给单个样本）；L4 关联文献（最后手段）。每字段只用本字段的解析模式：候选串先按字段分别过模式，不过模式的不进字段、不留原文。提取产出两份文件：拟用 JSON（`expression-metadata.proposed.json`，与现行 JSON 同结构）与逐行 trace（每行旧值、新值、证据来源标签）。拟用文件不直接覆盖现行 JSON，复核通过后才晋升。参考实现：`pilot/pull_classified_evidence.py`（拉三层证据）、`pilot/extract_classified.py`（分类提取）、`pilot/validate_reference.py`（对照参考表验证）。提取器以合并版为准（2026-11-24 全量重跑所用版本，见 §3.17；并行期间各 agent 各改自有副本、最后由协调人合并统一重跑，见 BATCH_PLAN.md §4 第 9 步）。
15. **分类提取（字段细则）**：treatment——候选源是同一处理的多个备选，只取第一个能解析的源；同一值内的多因子用 `+` / `;` / `and` 拆开、逐个解析、`;` 拼接（主因子在前），同因子去重（取信息最全的一个，盐与氯化钠视为同一因子）；剂量与时长保留（浓度、时长、胁迫等级只在无剂量/时长时保留）；零剂量或零时长（0h、0 天、0 mM）即对照臂；化学缩写展开；发育阶段也可作处理候选（可含接种后时间点）；渗透胁迫以水势值作剂量；光周期（短日照/长日照）是独立因子。genotype——转基因解析只认基因名+种类（过表达/敲除/敲低/显性抑制），同基因同种类取带系号的解析；基因名与种类之间可连字符；“过表达 of 基因”取介词后的基因名，不取介词本身；基因名前缀重复一次的去重；系号可取自值尾的 `-数字`；品种回退只从品种/分离株属性取，且只收名称样值（见 §3.16）。tissue——小写、单数化、去重复编号、多组织用 `;` 拼、超长描述值坍缩为最长的已知器官短语、常见拼写错误归一。growth_time——只收带单位的时间量，词数转数字，无单位的裸数不用。
16. **分类提取（垃圾值过滤）**：以下现行值在无新证据时清除或归一，不保留——裸数字（纯数字串无任何因子/基因含义）；字面词“品种”本身；基因名为停用词的解析结果（介词、冠词、属名、通用词）；含本物种学名词的值；发育阶段短语、处理臂码、单字母、样本编号串冒充的基因型；冗长的野生型表述归一为标准野生型值。处理臂码（如研究内自编的处理代号）无化学名可考时可暂留，但必须在 trace 中标记为臂码、不得冒充化学处理。
17. **合并版提取器规则（2026-11-24）**：并行提取后由协调人统一合并的规则集，下一轮直接用合并版提取器，不再从各 agent 副本拼装——
   - **研究级标题守卫**：以研究为单位统计本物种证据里出现的 distinct 实验标题；只有一个的视为研究级标签，只作词汇、不进样本级候选。研究分组键用行自身的 study_accession（证据表的 study 列可能错位或为空，不可作分组键）；项目号识别须覆盖全部项目号形态，不只认其中几类。守卫是否生效必须用目标行的输出值验证，不能只看代码是否在位。
   - **样本标题补全**：样本库记录的 sample_title 是 L2 候选（与样本标题同级）；标题/别名栏位里形如登录号的值先清空；超过长度上限的描述原文（研究/数据集叙述）不作样本级证据。
   - **基因名停用词**：普通词（胁迫词、处理词、插入/缺失等通用词）与本物种学名词命中即拒绝，不进基因型；基因符号前粘连的物种加词要剥离；属名+种加词开头的整串只留品种部分，剥空即拒；物种/组织词只有构成整串时才拒绝，不按子串；单个分类学命名人缩写没有第二处样本级字段佐证时丢弃。
   - **品种回退名称门**：回退值必须像名称——拒收通用名词、纯单位串、处理臂码形态、纯大写缩写、技术词、占位词及其拼写变体（下划线/连字符归一后比对）、月份/季节词（歧义月份/季节名除外，宁可保留品种名也不误删）、发育或泛称词、植株编号、布尔值、含“品种”泛称的值、单个国家名。品种属性排在分离株之前；弱来源（品种/分离株/别名/描述）只填空值，不覆盖已有实值（旧值本身是垃圾时可覆盖）；品种/分离株来源只剥 `_数字` 后缀，保留 `-数字` 的生态型名；值首尾引号剥离（剥属名后再去一次）；双品种用 `and` 连接时未拆分（已知缺口）。
   - **温度与气体**：数值+摄氏单位按阈值映射为冷/热（温度值作剂量保留）；共同生长温度（伴随干旱/浇水/土壤湿度、无冷热明示）不作热因子；环境二氧化碳归对照，不作升高二氧化碳；二氧化碳需词边界且需修饰词；贮藏语境不判二氧化碳处理；遮阴与臭氧各立因子（遮阴在光周期分支之后）；菌根接种单列，不作感染。
   - **对照与否定**：对照短语先算标志、因子检测之后再据此返回对照；对照判定用非字母边界（下划线是词字符）；`control for X` 整值守卫；同一值同时出现对照与处理叙述视为研究设计，跳过该候选；复合对照词不算对照臂；否定式在因子匹配前剥离，无其他因子时否定式归对照；接种后时间短语不作接种因子。
   - **数值边界**：剂量/时长正则拒绝范围端点与连字符样本号；顺序时长（两段时长视为转移年龄）与多时点数量列表返回空；连字符高温识别；二氧化碳×高温并列保留两因子；裸剂量值原样保留作剂量，零剂量即对照；剂量单位含 g/L。
   - **组织标题守卫**：实验标题只有短、不含逗号、且至少含一个器官词时才作组织证据，否则保留旧值；组织值里的采样描述词（混合/合并/冷冻/对照/重复等）整段丢弃或从多词段中剔除；百分/相对深度描述保留整值，其余数字限定词折叠到器官；果实分层器官进器官词表；多词碎片无器官词时丢弃。
   - **生长时间**：时间单位含植物学时间量；连字符年龄解析；复数保留原文单复数（不做空改动）；小时单位可进；旧值也要过同一套模式——解析不出的旧处理长句清除或坍缩为因子（臂码可留但须在 trace 标为臂码）。
   - **置信度双向重算**：按 §3.13 重算时既有降级也有升级（字段齐全且无默认值可升）；品种回退的基因型与臂码处理至多 M。
   - **逐字段来源标签**：trace 四字段各有来源标签；清空类改动（值→空）是有效性拒绝，空标签正确，不补造来源。
   - **证据修复**：实验标题缺失的行可由公共库检索补标题（有源可补、无源记来源限制）；证据文件表头与每行列数须校验（修复脚本写坏表头会把 run 号读成标题）；证据文件混入非数据行时删行。

## 4. 策展规则（统一口径）

- genotype：无证据时默认 `WT`，必须在 `default_used` 留痕；命名品种、转基因系不给默认（留空）。
- confidence：H 仅当 tissue、treatment、genotype 三字段均为实证值（default_used 为空且 genotype 非空）；任一字段仍是默认值即至多 M；默认 control 或论文推断为 M；不确定留空并降档。
- tissue：照抄源值，仅做两处归一——全小写、去掉重复编号（如 `female bud1`→`female bud`）。
  不做同义词合并。
- growth_time：只接受时间量。BioSample age 的时间量可映射（如 `300 days`）；阶段名
  （dev_stage、WAF 除外——WAF 是时间量，可进）、月份点不进，记 EVIDENCE.md。时间单位含植物学时间量（如开花后天数等）；复数保留原文单复数，不归一为单数。
- treatment：多因子用 `;` 拼接，主因子在前（如 `jasmonic acid;15C`、`control;15C`）。分类提取的写法见 §3.15：因子+剂量+时长（如 `盐 150mM 6d` 的结构），等级词只在无剂量/时长时保留；零剂量/零时长即对照。
- 分类提取置信度：经分类提取改动的行，置信度按 §3.13 双向重算（字段齐全且无默认值可升至 H，有默认值则降至 M）；臂码处理与品种回退的基因型至多 M；提取无新证据的行保持原置信度。
- default_used：多值用 `;` 拼接，顺序固定 treatment 在前、genotype 在后
  （如 `treatment=control;genotype=WT`）。
- source_sha256：记基线 TSV（NCBI 为主拉取的第一份源文件）；补充源文件的哈希放 EVIDENCE.md。
- GSA-only 行：进 JSON。study_accession 用 PRJCA（有则用，无则 CRA）；run_accession 用 CRR 号；
  confidence 降一档（最多 M）；来源写进 EVIDENCE.md。
- NCBI-only 行：进 JSON，以 NCBI runinfo 为凭，confidence 降一档。

## 5. EVIDENCE.md 必须有的内容

计数（NCBI/ENA/GSA 各自数字与 diff 定性）、接受名与异名表、单细胞剔除数、NGDC/文献/
多组学库核查结果、补充行策略审计（各策略行数）、样本属性缓存位置、默认矛盾扫描结果与裁定记录、
不确定字段及处理、遗留问题（带“待复查”标记，不阻塞主流程）、分类提取 trace（逐行旧值/新值/证据来源）与验证结果、合并版提取器版本（sha256）与复核扫描（新值/沿用旧值分开计数）。

## 6. 禁止

编造登录号/PMID/BUSCO/基因数；下载 FASTQ；把缺失写成 0；静默跳过未知 run/gene；
用文件数或 mtime 代替 SHA-256；未经授权写生产库、部署、commit、push。
