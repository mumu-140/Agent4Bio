# 经验与坑（试点实测，2026-11-23）

> 每条都有日期、证据和修复办法。策展前通读；踩到新坑时按同样格式追加，注明日期与证据。

## 检索类

### #1 表上 taxid 查成了另一个物种（2026-11-23）
- **事实**：表上 taxid 查得 0 行。实测：该 taxid 是另一个物种的接受名；目标物种另有 taxid，ENA 与 NCBI 计数一致，另有属级登记行。
- **教训**：先解析接受名再查数；名搜索的第一个命中可能是另一个物种。
- **修复**：NCBI taxonomy + POWO/FoC 双重核对；异名表写进 EVIDENCE.md；源 TSV 换成合并版，
  新旧 sha256 都记。

### #2 ENA tax 查不到 NCBI 有的行（2026-11-23）
- **事实**：NCBI 比 ENA 多数十行，差的全是 DDBJ 研究（两个 BioProject）；ENA 存有这些 run，但记录的 scientific_name 与 tax_id **为空**，tax_eq 查不到。
- **教训**：ENA tax_eq 不可单独作准。
- **修复**：NCBI 为主 + ENA 按 BioProject 补拉 + 逐物种 NCBI−ENA diff，差异逐条定性。

### #3 ENA 滞后 NCBI：近期 DDBJ 提交未镜像（2026-11-23）
- **事实**：近期 DDBJ 提交的一个 run，ENA 查只返回表头，NCBI 已加载并经 runinfo 核实；同一研究的另一个 run 是近缘种，正确排除。
- **修复**：NCBI-only 行进 JSON，以 NCBI runinfo 为凭，confidence 降一档（M）。

### #4 NCBI esearch Count 计 experiment 不计 run（2026-11-23）
- **事实**：NCBI Count 与实际行数差 1——一个 experiment 带 2 个 run，同一 样本，ENA 核实。
- **修复**：计数后必须 efetch runinfo 展开到 run 再比对集合。

### #5 SAMD 号走 NCBI efetch 会返回人类 GTEx 记录（2026-11-23）
- **事实**：两个试点策展人独立踩中——SAMD 样本号经 NCBI efetch 返回毫不相干的人类 GTEx 记录。
- **修复**：SAMD 样本属性走 ENA sample API（`https://www.ebi.ac.uk/ena/browser/api/xml/<SAMD>`），
  SAMN 走 NCBI。

### #6 ENA 列顺序与请求不一致（2026-11-23）
- **事实**：ENA portal API 返回列按自己的顺序（run_accession 在前），不是请求顺序。
- **修复**：解析必须表头驱动，禁止按列位置取。

### #7 GSA 被 JS 校验拦，curl 无用（2026-11-23）
- **事实**：GSA 浏览/搜索页返回 SecurityCheck 页（JS cookie 校验）；沙箱与工作节点的 curl 均被拦。
  实测：经代理 curl 浏览页返回 200，但正文只有校验页。真实浏览器可正常通过。
- **修复**：CRA→CRR 枚举走浏览器任务；取不到 CRR 的先记 CRA 级并标注“CRR 未枚举”，不编 CRR 号。
  **不**绕过校验（不复现 token、不伪造 cookie）。

### #8 属级登记会漏物种（2026-11-23）
- **事实**：有行登记在属级 taxid 下，tax_eq 查不到。
- **修复**：属级登记须经 BioProject 题名/描述 + 论文双重核实为本种才计入，写明证据。

## 策展类

### #9 默认值不留痕等于没做（2026-11-23）
- **事实**：试点里某物种上百行 genotype=WT 全是默认、未留痕；另一物种几行 control 缺 treatment 留痕；default_used 多值顺序不一。
- **修复**：每个默认值都留痕；多值顺序固定 treatment 在前、genotype 在后；试点已全部修完。

### #10 两个物种共用一个表上 taxid（2026-11-23）
- **事实**：两个物种表上共用一个 taxid，规范名也相同，计数是同一个数——表本身可能把其中一个的 taxid 写错了。
- **修复**：策展时按接受名重查，计数仅作体量参考；结论写 EVIDENCE.md。

### #11 杂交种没有独立 taxid（2026-11-23）
- **事实**：某杂交种表上 taxid 是亲本的，杂交种本身无独立 taxid，NCBI 计数 0。
- **修复**：按杂交名/亲本双通道查；0 计数不等于无数据，走 ENA/GSA/文献再定。

### #12 多组学库五物种均无增量（2026-11-23）
- **事实**：Phytozome / TreeGenes / PlantGenIE 对试点物种均无 RNA-seq 增量；个别物种另有专库，是镜像、无增量。
- **教训**：多组学库是必查项，但别指望它补数；主渠道仍是 INSDC + GSA。

## 工程类

### #13 工作节点出网必须显式走实验室代理（2026-11-22/23）
- **事实**：shell 无直连出网，出网须显式走实验室代理（直连/warp 两条线，速度差异大，长下载选快的那条，见环境配置）。
  单行 `export https_proxy=$http_proxy` 会展开为空导致 HTTPS 绕过代理、超时。
  aria2c 走代理不出文件（两次实测），别用。
- **修复**：长下载用 `setsid … </dev/null >/dev/null 2>&1 &` 脱离；`pkill -f` 模式串不得出现在
  调用 shell 自己的命令行里（用精确 PID，或 `[c]url` 括号技巧且模式串不在别处出现）。

### #14 计数脚本被运行时重启打断，断点续跑救了它（2026-11-23）
- **事实**：计数脚本跑到九成时运行时重启把它杀了；因脚本按种增量写盘且跳过已计物种，重跑很快补完。
- **修复**：所有批量脚本必须可断点续跑（增量写盘 + 跳过已完成）；长任务一律 nohup + 日志。

### #15 后台报的数字，亲自复算一遍再说（2026-10-15）
- **事实**：把后台调研报的数字当核实过的事实用了，没对台账、没注明统计口径，被抓包。亲手重验后：其中一个数无可复现口径、应作废。
- **修复**：任何要写进交付的数字，亲自对一手来源复算；注明统计口径；证据进 git/落盘，不只放工作区。

## 批量后复核（2026-11-24）

### #16 补充路径漏了策略过滤（2026-11-24）
- **事实**：批量补充行并入时未按 library_strategy 过滤，DNA 类与小 RNA 行混进 JSON，事后全量审计才发现。
- **修复**：并入前按策略过滤（STANDARD.md §0），策略缺失人工定性，审计表留档。

### #17 H 口径不严（2026-11-24）
- **事实**：批量中出现 H 行但 genotype 为空（默认值）。
- **修复**：H 仅当三字段均为实证值（STANDARD.md §4），复核按此重算。

### #18 样本属性缓存缺失（2026-11-24）
- **事实**：部分 agent 未留样本属性缓存，复核无法离线做，只能重新联网抓。
- **修复**：每物种必留缓存（STANDARD.md §3.11）。

### #19 DDBJ 探路端点错了（2026-11-24）
- **事实**：当时按猜测的 getentry 路径探 DDBJ 样本，返回的只是检索页，误判为“探不到”；正确入口是 DDBJ Search 条目页（STANDARD.md §3.10），浏览器与文本抓取均可直达。
- **修复**：探路先核对官方入口文档，不凭猜测的 URL 下结论。

### #20 研究的 run 列表不一定连续（2026-11-24）
- **事实**：一次浏览器复核只读了某研究的前一批 run（按首尾号推断为连续区间），漏了十余行（该研究的 run 号不连续）。
- **修复**：复核清单以本方 JSON 的 run 列表为准，逐条对表，不得按区间推断；研究页有分页的要翻完。

### #21 默认矛盾扫描事后补（2026-11-24）
- **事实**：批量交付后才发现默认字段与样本原文矛盾，事后裁定多花一轮。
- **修复**：扫描做进批量流程、交付前完成（STANDARD.md §3.12）。

### #22 会话断点续跑（2026-11-24）
- **事实**：批量执行方会话被服务商暂停打断，协调人只能按残件重建报告，部分结论无法证实；分组只按 experiment 数均衡，物种数多的一组逐物种抓属性、建缓存的开销明显倾斜。
- **修复**：agent 每完成一物种即落盘进度标记与日志，协调人只引用 agent 自写日志，不重建报告；分组按 experiment 数与物种数双维均衡（BATCH_PLAN.md §2）。

### #23 逐字照搬会把样本编号写进字段（2026-11-24）
- **事实**：早期提取版本把候选原文不经解析直接填进字段，结果处理栏出现重复编号、实验标题原文，基因型栏出现样本编号。
- **修复**：取消逐字回退；候选串必须过本字段的解析模式，不过模式的不进字段（STANDARD.md §3.14）。

### #24 多候选源不是多处理（2026-11-24）
- **事实**：一次提取把全部候选源的解析结果都拼进处理栏，出现同一因子的重复（如带剂量的盐与裸盐并列）与矛盾组合（处理因子+对照并列）。
- **修复**：候选源是备选关系，只取第一个能解析的源；`+` 拆分只在单个值内做；同因子去重取信息最全者（STANDARD.md §3.15）。

### #25 基因名解析的介词与连接陷阱（2026-11-24）
- **事实**：三种解析错误都出在基因名捕获上——“过表达 of 基因”把介词当基因名；基因名与“过表达”之间用连字符时旧模式要求空格，漏解析；样本名里基因家族前缀写了两遍，基因名带双倍前缀；值尾的分隔符残留进基因名。
- **修复**：介词后取基因名；基因名与种类之间空格与连字符都接受；去重家族前缀；捕获后去掉尾部分隔符；捕获到的基因名再过停用词表（STANDARD.md §3.15–3.16）。

### #26 品种回退的拒收表（2026-11-24）
- **事实**：品种回退一度从标题/别名取词，把处理臂码、发育阶段短语、单字母、物种名+组织构成的样本名串都填进了基因型栏。
- **修复**：回退只从品种/分离株属性取，只收名称样值；拒收处理臂码、阶段短语、纯数字、单字母、含物种学名词或组织词的值、多下划线的样本编号（STANDARD.md §3.15–3.16）。

### #27 零剂量即对照，但“10 天”里的 0 不是零（2026-11-24）
- **事实**：零剂量/零时长（0h、0 天、0 mM）是对照臂；但一次验证把“10 天”误判为零（正则只看了 0，没看前一位数字）。
- **修复**：零值判断要求 0 不是更大数字的一部分（前一位不能是数字）；提取与验证两侧同规则（STANDARD.md §3.15）。

### #28 复制后缀会破坏词边界（2026-11-24）
- **事实**：处理值尾的复制编号（如 `_1`）让词边界模式失效，盐与渗透剂的因子识别不到，整行被迫保留原文。
- **修复**：解析前先去掉值尾的复制编号（STANDARD.md §3.15）。

### #29 光周期是独立因子（2026-11-24）
- **事实**：一批短日照处理行因因子表里没有光周期，处理栏长期留空；其基因型来自样本描述里的“突变体”字样，与光周期无关。
- **修复**：短日照/长日照/光周期各立因子，时长从同一串里取（STANDARD.md §3.15）。

### #30 渗透胁迫的剂量是水势（2026-11-24）
- **事实**：渗透剂处理值里的水势（如 -0.6 MPa）不在剂量单位表里，整行无法解析。
- **修复**：渗透剂因子单独处理，水势值作剂量保留（STANDARD.md §3.15）。
## 合并版复核（2026-11-24）

### #31 研究分组正则须覆盖全部项目号形态（2026-11-24）
- **事实**：单标题研究守卫的分组正则只认部分项目号前缀时，守卫恒为空、从未触发，错误值照常写进字段；扩到全部项目号形态后才生效。
- **修复**：分组正则覆盖全部项目号形态；守卫是否生效用目标行的输出值验证，不能只看代码是否在位（STANDARD.md §3.17）。

### #32 证据 study 列可能错位或为空（2026-11-24）
- **事实**：证据文件的 study 列有整批行是平台串（列错位），另有行该列为空而 JSON 行内有项目号；按证据列分组会分错研究。
- **修复**：分组键用行自身的 study_accession，证据列只作兜底（STANDARD.md §3.17）。

### #33 修复脚本会写坏证据表头（2026-11-24）
- **事实**：一次证据修复把实验标题表的表头写成 4 列（实际固定 5 列，含 run 号），解析器于是把 run 号读成实验标题。
- **修复**：修复后逐行校验列数与 run 号列；表头恢复为规范名（STANDARD.md §3.17）。

### #34 证据文件会混入非数据行（2026-11-24）
- **事实**：样本记录表里混入一行连接错误文本，险些被当样本读入。
- **修复**：证据文件落盘后校验每行形状，非数据行删行（STANDARD.md §3.17）。

### #35 实验标题缺失可补但有源限制（2026-11-24）
- **事实**：样本库无实验标题的部分行可由公共库检索补回标题；另一些来源的标题无公开可补渠道。
- **修复**：有源可补、无源记来源限制，不编造标题（STANDARD.md §3.17）。

### #36 0 行物种不跑证据拉取（2026-11-24）
- **事实**：对 0 行物种跑证据拉取时，空查询返回的是无关记录（甚至其他类群的实验），既浪费也可能被误当证据。
- **修复**：0 行物种拟用文件照抄现行、trace 为空，不造 evidence/ 目录（BATCH_PLAN.md §4 第 9 步）。

### #37 并行副本会分叉，收敛靠合并重跑（2026-11-24）
- **事实**：4 个 agent 各改自有提取器副本，产物一度来自不同版本，来源不可追溯；协调人合并成统一提取器后全量重跑才收敛。
- **修复**：规范提取器是合并版；并行期间各改副本、改动记变更记录、最后统一合并重跑（BATCH_PLAN.md §4 第 9 步）。

### #38 弱来源不得覆盖强值（2026-11-24）
- **事实**：品种回退与别名/描述来源一度覆盖已有的真实基因型与处理值（如已有基因型被回退值覆盖、对照被栽培描述覆盖），有变好也有变差，混在同一规则里。
- **修复**：弱来源只填空值，不覆盖已有实值；旧值本身是垃圾时才可覆盖（STANDARD.md §3.17）。

### #39 品种回退需要名称门（2026-11-24）
- **事实**：占位词变体、通用词、单位串、处理臂码、月份词、植株编号、布尔值、含“品种”泛称的值都会经品种回退混进基因型；歧义词一刀切又会误删真实品种名。
- **修复**：回退值必须像名称，上述形态拒收；歧义词宁可保留品种名也不误删（STANDARD.md §3.17）。

### #40 组织不能从标题无条件取（2026-11-24）
- **事实**：实验标题作组织证据时，平台串与样本码一度覆盖了原本正确的组织值，整批行被写错。
- **修复**：标题只有短、无逗号、且至少含一个器官词时才作组织证据，否则保留旧值（STANDARD.md §3.17）。

### #41 否定与对照语义（2026-11-24）
- **事实**：否定前缀未剥离时，未处理/未接种被写成处理因子；对照标记被因子词抢占；双臂设计叙述被当成单因子；复合对照词被当成对照臂。
- **修复**：否定式在因子匹配前剥离；对照短语先算标志、因子检测之后再返回；复合对照词不算对照臂；双臂设计叙述跳过该候选（STANDARD.md §3.17）。

### #42 数值边界：范围端点与连字符号不是剂量/时长（2026-11-24）
- **事实**：范围端点、连字符样本号、顺序时长、多时点数量列表一度被当成剂量或采样年龄写进字段。
- **修复**：剂量/时长正则加前视拒绝范围端点与连字符样本号；顺序时长与多时点列表返回空（STANDARD.md §3.17）。

### #43 旧值也要重解析（2026-11-24）
- **事实**：解析不出的旧处理长句长期原样保留在处理栏；生长时间复数归一的空改动占一轮改动量的一半以上，没有任何信息增益。
- **修复**：旧值过同一套模式，解析不出的清除或坍缩为因子；复数保留原文单复数（STANDARD.md §3.17）。

### #44 报告引用的路径必须存在（2026-11-24）
- **事实**：一轮并行提取的报告引用了一个不存在的复核目录，点名的 6 个证据文件只有 2 个真实存在（其余在另一目录下）；与上一轮批量交付缺失复核文件是同一类问题。
- **修复**：引用路径与文件名前先核对存在性；复核证据集中到 `review/classified-20261124/`（见该目录 README）。

### #45 置信度只降不升是系统性低估（2026-11-24）
- **事实**：提取器只有 H→M 降级分支、没有任何 M→H 升级路径，字段齐全且无默认值的行长期停在 M。
- **修复**：置信度按标准双向重算，既降级也升级（STANDARD.md §3.13、§4）。
