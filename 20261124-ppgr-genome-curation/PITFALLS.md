# PITFALLS：基因组检索、下载与策展的常见误区

以下规则从实际策展与独立 QC 经验提炼，不绑定物种、登录号、样本、数据库发布版本或历史任务。对当前目标必须重新核验证据。

| 风险 | 判定与正确处理 |
|---|---|
| 1. 物种名与 taxid 可能错误 | 核对接受名、异名、分类等级、样本与数据库 taxon；不同亚种、变种、杂交材料不能自动等同；同一组装的分类别名只计一次。 |
| 2. 同物种不等于同组装 | 目录名、文件名和物种名都不是版本证据；核对 accession.version、材料、序列数、长度与发布记录。大规模越界优先找回同版 FASTA/GFF，不通过删行掩盖错版。 |
| 3. 备选组装不能替代指定版 | 独立验收、单独登记备选参考；未经授权不更换目标版本，不把备选计入指定目标完成数。 |
| 4. 同长度不等于同序列 | 逐序列比较正向与反向互补核酸、hash 和覆盖范围；遇末端差异、插缺或局部重排必须定位并验证受影响特征。反向互补须同时转换坐标、strand 并核对 CDS；不按染色体编号猜测。 |
| 5. seqid 重命名需要证据 | 以同版 assembly report 的一对一别名或独立核酸同一性建立映射；仅改确证的 seqid 与相关指令，保留映射表与源 GFF。不得跨近缘种、跨材料套用。 |
| 6. 优先恢复原生配对 | 从论文、作者或机构专库寻找同一发行包的 genome 与 annotation；第三方或官方归档中的另一组装不能直接混配。 |
| 7. 官方 checksum 通过不保证坐标兼容 | 文件可完整下载但 GFF 仍可能引用 FASTA 不存在的 scaffold。先寻回缺失序列，无法恢复时仅在明确授权下生成派生兼容 GFF，逐项记录来源、排除范围、父子闭包及各类特征保留比例。 |
| 8. 机械过滤会造成系统性缺失 | 不要以固定损失百分比或少量越界自动放行；评估问题位置、缺失基因/转录本、下游分析偏倚与用户用途；严重缺失保持 REVIEW，严禁裁切坐标或删除原件。 |
| 9. CDS/蛋白链方向陷阱 | 作者提供的 CDS/PEP 也可能把负链按基因组正向导出。按转录本从 GFF 独立提取、负链逆序反向互补，检查 phase、遗传密码和翻译结果；不把源 PEP 当绝对真值。派生数据记录版本、算法、hash。 |
| 10. gene、transcript 和细胞器计数混淆 | 无显式 gene feature 时不拿 mRNA 数填 gene_count；基因、转录本、CDS 分别计数，并区分核、细胞器和未定位序列。 |
| 11. 合法分段不等于重复错误 | GFF3 同 ID 可表示不连续特征；检查类型、seqid、strand、Parent 及分段语义，不能盲目去重。 |
| 12. 第三方预测或重注释不是原版 | 区分原作者注释、官方注释 release、独立重注释、自动预测。即使技术 QC 通过，也不冒充其他来源或未经授权替代目标注释；区分不同 haplotype。 |
| 13. T2T 等标签不是身份凭证 | T2T、chromosome-level、最新版不能证明同一组装；分别核对 dataset version、assembly version、annotation release、材料和 accession.version。 |
| 14. 论文或 BioProject 存在不代表文件可用 | 区分 raw reads、exome、transcriptome、organelle、基因家族研究、完整核组装与结构注释；回查 Data Availability 和真实文件清单，未确认文件仅记候选。 |
| 15. 403/401 不等于没有数据 | 查公开 API、记录版本与 file ID、合法下载页面；有限重试、使用已授权网络或普通浏览器，必要时交付人工链接清单。尊重访问限制；429 按 Retry-After 退避。 |
| 16. 通用 URL 尾名与归档混杂 | content/download 等尾名可能导致路径冲突；以真实元数据和物种/版本/文件角色确定唯一目的路径。检查归档成员、路径穿越和格式；不把 CDS/PEP/RNA 当 genomic FASTA。 |
| 17. 非空文件可能是残片或错误页面 | HTTP 200、mtime、退出码 0、非空文件均非验收。核对魔数、实际大小、官方校验值、全量 gzip CRC/归档可读性与 FASTA/GFF 解析；失败按证据续传或重新获取，用户暂停项不再重试。 |
| 18. 过时报告会重复劳动或虚报进度 | 每次读取实际任务表、正式索引和队列，复算当前统计、明确分母；历史快照和问题子集不能当实时全集。区分目标、别名、备选、HOLD。 |
| 19. 缓存和旧脚本可能隐含旧状态 | 不因非空文件而 skip；API 分页取全，核对 taxid；长度或 QC 缓存以源 hash 和参数版本绑定。审查旧脚本是否硬编码目标、阈值、输出或覆盖；不可直接重建正式索引。 |
| 20. 过度重试、越权和资源浪费 | 每文件设合理 retry budget、超时、并发与存储预算；仅用已授权渠道。记录失败根因及人工交接信息，继续其他获授权目标，不因首个失败或成功就结束整批。 |

复用方法：先确认当前物种、样本和 accession.version，重新验证来源、校验值及坐标关系，再选择相应修复原理。历史结论不替代当前证据。
